## Recommended stack

For a 24-hour build, use **one Next.js app, deployed on Vercel, with no separate backend.**

| Layer | Choice | Why |
|---|---|---|
| Framework | **Next.js (App Router) + TypeScript** | Pages, routing, server components and API routes all live in one codebase. Server rendering also makes search and product pages load fast. |
| Styling | **Tailwind CSS + shadcn/ui** | You get polished, accessible pieces (sheet, dialog, select, toast, skeleton) that you own and can restyle to look like Amazon. |
| Icons | lucide-react | Comes with shadcn. |
| Product data | **A seeded JSON catalog in the repo** (about 100–200 products across 6–8 categories) | You don't need a database to make shopping feel real. Reading from a file is instant and can't break during the demo. |
| Cart state | **Zustand with localStorage persistence** | The cart survives a refresh, the header count updates live, and there's no setup. |
| Checkout | A mock multi-step flow. Add **Stripe Checkout in test mode** only if there's time left. | The flow itself is what impresses. Payment is a bonus. |
| Images | `next/image`, with remote patterns pointed at the product image source | Handles image optimization and lazy loading. |
| Deploy | **Vercel**, connected to the GitHub repo | Every push deploys and you get preview URLs. You can deploy in hour one. |

**What I'd skip:** a database, real authentication, a separate API server, a monorepo, and Redux. Each one costs hours and the person judging won't see the difference. If you later want persistent orders or accounts, add Supabase or Neon Postgres then. Keep data access behind a small `lib/catalog.ts` so that swap is easy.

## The shopping flow to build well

1. **Home**: hero carousel, category tiles, "deals" rows
2. **Search and category results**: query, filters (price, rating, Prime), sorting, pagination
3. **Product page**: image gallery, price and discount, rating summary, buy box (quantity, Add to Cart, Buy Now), reviews, "customers also bought"
4. **Cart**: change quantities, remove items, save for later, subtotal, free-shipping progress bar
5. **Checkout**: address, then delivery speed, then payment, then review order
6. **Order confirmation and an "Your Orders" page** (stored in localStorage)

These details make the UI feel polished for little effort:
- a sticky header with a search box that has category scoping and suggestions, plus a live cart count
- loading skeletons and toasts when items are added
- a slide-out cart drawer
- consistent currency and rating components
- empty states for no results and an empty cart
- a layout that works on phones
